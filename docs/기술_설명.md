# AutoML-Agent 기술 설명 (4조)

카드 거래 데이터로 **고객층(성별×연령구간 6개) × 업종 대분류(8개)의 다음 달 지출이 늘지 줄지** 예측하는 모델을,
에이전트가 전처리·변수·모델·하이퍼파라미터를 스스로 정하며 만드는 프로그램입니다.
설계 근거와 결정 과정을 담은 구현계획서(`docs/구현계획서.md`)는 실데이터 요약 수치가 들어 있어 팀 내부에만 두고 저장소에는 올리지 않습니다.

## 1. 실행법

저장소 안의 가상환경(`.venv`)을 씁니다. 모든 명령은 저장소 최상위 폴더에서 실행합니다.

```powershell
.venv\Scripts\python run.py --check          # ① 설정 요약과 오류 확인 (학습 안 함). 설정을 고친 뒤 항상 먼저
.venv\Scripts\python run.py                  # ② 실데이터 전체 실행 (원본 → 보고서)
.venv\Scripts\python run.py --raw ..\데이터\가짜데이터\fake_raw.csv     # 가짜데이터로 시험
.venv\Scripts\python run.py --replay ..\결과\03_agent\runs\<실행폴더>  # 이전 실행의 LLM 답을 그대로 써서 재현
```

- 결과는 `..\결과\03_agent\index.html`을 더블클릭하면 실행 목록이 열리고, 각 실행의 `report.html`로 이동합니다.
- 가짜데이터(`..\데이터\가짜데이터` 안의 파일)로 실행하면 결과는 `..\결과\테스트_agent`, 행 단위 파일은 `..\데이터\가짜데이터\secure`로 따로 갑니다.
- 가짜데이터 만들기: `.venv\Scripts\python tools\make_fake_raw.py --rows 300000`
- 안전장치 자동 점검: `.venv\Scripts\python tools\self_test.py` (가짜데이터)
- 노트북 baseline(테스트 0.5197) 재현 점검: `.venv\Scripts\python tools\reproduce_baseline.py` (실데이터, 정답표가 panel_monthly.csv와 1원 단위로 같은지도 확인)
- 결과 폴더에 지역 이름이 새지 않았는지 점검: `.venv\Scripts\python tools\check_results.py` (`--fake`는 가짜데이터 결과)

## 2. 설정 (비전공자용)

`config.yaml` 하나로 모든 것을 정합니다. 항목마다 한글 설명이 붙어 있습니다.

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 후보 모델 빼기·넣기 | `후보모델 > 모델이름 > 사용: 예/아니오` |
| 모델 탐색 범위 바꾸기 | `후보모델 > 모델이름 > 좁은범위` |
| 에이전트가 시험할 변수·전처리 | 각 항목의 `시험: 예/아니오` |
| 채택 기준을 엄격하게/느슨하게 | `판단규칙` |
| 수정 시도 횟수 | `판단규칙 > 수정_최대횟수` |
| LLM 사용 | `LLM > 모드: 규칙 / ollama / openai` |

LLM을 쓰려면:
- **ollama** (이 컴퓨터 안에서 실행, 데이터가 밖으로 안 나감): ollama 앱을 켜고 `ollama pull qwen2.5:7b` 후 `모드: ollama`
- **openai**: `.env.example`을 `.env`로 복사해 `OPENAI_API_KEY=` 뒤에 키를 쓰고 `모드: openai`. `.env`는 GitHub에 올라가지 않습니다 (이미 설정된 환경변수가 있으면 그쪽이 우선).
- LLM에게는 업종 이름·집계 통계·검증 점수·지역 코드만 보냅니다. 연결이 안 되면 규칙 모드로 자동 대체됩니다.

## 3. 구조

```
run.py            실행 버튼. 전체 흐름이 이 파일의 run_all() 열 줄에 보임
config.yaml       설정 (메뉴·판단 규칙)
state.py          작업 노트 양식 (에이전트들이 차례로 채우는 칸)
common.py         공통 도구 (설정 검사, 점수 계산, 채택 규칙)
agents/
  raw_agent.py    [0] 원본 CSV 점검·정제 → 정제 원본 parquet (원본을 읽는 유일한 곳)
  planner.py      [1] 설정 검사, 처음 레시피 A·B
  data_agent.py   [2] 정답표(고정) + 레시피별 변수표, 사전 점검(🟢🟡🔴)
  model_agent.py  [3] 후보 14개(+선택 2개) × 하이퍼파라미터 × 롤링 검증 3회차 → 채택 규칙으로 선택
  calendar_model.py  [3] 후보 '달력방향': 다음 달이 더 긴지로 달 방향 결정
  bottomup.py     [3] 후보 '중분류합산': 중분류 변화를 예측해 더함 (기본 끔)
  problem_lookup.py   변수표 행 → 문제(기준월·고객층·업종) 대응 (위 두 후보가 씀)
  reviewer.py     [5] 수정안 시험 루프(check), 보고서(report)
  executor.py     [4] 테스트 단 1회, 월별 갱신 실험, 예측표
llm.py            LLM 호출 (규칙/ollama/openai)
prompts/          LLM 지시문 (일반 글)
dashboard.py      report.html, index.html 그리기 (계산 없음)
tools/            가짜데이터 생성기, 자동 점검
```

흐름: `[0] 원본 → [1] 계획 → [2] 정답표·변수표 → [3] 검증 → [5] 수정(사전 점검 → 검증 → 채택/기각, 최대 3회) → [4] 테스트 1회 → [5] 보고`

## 4. 평가 방식 (한 달 = 48문제)

| 단계 | 학습 (기준월) | 채점 (기준월) |
|---|---|---|
| 롤링 검증 1~3회차 | 3~5월 / 3~6월 / 3~7월 | 6월 / 7월 / 8월 (합계 144문제) |
| 최종 테스트 (1회) | 3~8월 | 9~11월 (144문제) |

- 정답(다음 달 증가/감소)은 원본 전체로 만들고 레시피와 상관없이 고정합니다. 레시피마다 같은 문제인지 코드로 확인합니다.
- 새 레시피·모델은 **짝 비교 부트스트랩 90% + 상승폭 0.02 + 3개월 중 2개월 상승**을 모두 넘어야 채택됩니다.
- 테스트는 고르는 데 쓰지 않습니다. 처음 레시피와 최종 레시피를 테스트에서 나란히 채점해, 최종이 더 낮으면 "검증 과적합 의심" 경고를 띄웁니다.

## 5. 환경과 측정값

- Python 3.13, duckdb 2.0, pandas 3.1, scikit-learn 1.9, lightgbm 4.7 (저장소 안 `.venv`)
- 가짜데이터 30만 행 기준: 레시피 1개 검증(후보 86개 × 3회차) 약 6~10초, 전체 실행 약 35초
- 실데이터(약 5,000만 행): 첫 실행 약 5분 (원본 정제 약 4분), 이후 정제 원본을 재사용해 수정 3회 기준 약 1분

## 6. 데이터 관련 메모

- 카드거래 명세는 `..\데이터\데이터명세\데이터명세서_AI부트캠프_2026_set1_품목데이터.xlsx` 안에 있습니다 (파일 이름의 set1/set2가 내용과 반대).
- 명세서의 파일명은 `uos_ai_2025_set1_out.csv`, 실제 파일은 `uos_ai_set1_out.csv`입니다. 둘 다 찾아봅니다.
- 비수도권은 시군구가 시도로 묶여 있어(명세서 익명처리), 지역 '세부' 단위는 수도권만 시군구입니다.
- 원본의 '12칼럼이 모두 같은 행'은 익명처리로 생긴 정상 행일 가능성이 커서 **지우지 않고 합산**합니다. 원인 진단은 보고서 '원본 점검'에 있습니다.

## 7. 보안

- 원본 CSV는 `agents/raw_agent.py`만 읽습니다. 행 단위 파일(정제 원본, utf-8 사본, 임시파일), 지역 코드↔이름 대응표, 오류 상세는 보안 폴더에만 저장합니다.
- 결과 폴더·화면·LLM에는 집계값만 나갑니다. 지역은 코드(S01, C001, R001)로만 나갑니다.
- 오류가 나면 화면에는 오류 종류만 나오고, 상세는 보안 폴더의 `error_*.log`에 저장됩니다 (원본 내용이 섞일 수 있어 공유 전 확인).
