# 작업 이어하기 (2026-11-20 기준)

다음 작업자(사람 또는 Claude)가 바로 이어서 할 수 있도록 현재 상태와 남은 일을 적는다.

## 현재 상태

- **6개 에이전트가 모두 LLM으로 생각**하도록 구현 완료 (원본·계획·데이터·모델·실행·검토). 도구 호출(최대 3회)로 집계를 조회한 뒤 결정하고, 코드가 검사.
- 규칙 모드(LLM 없음)·OpenAI 모드 모두 실데이터에서 끝까지 동작 확인. 자동 점검 `tools/self_test.py` 5/5 통과, baseline 재현(0.5197) 확인.
- 에이전트별 모델: 계획·모델·검토·실행 gpt-4.1, 원본·데이터 gpt-4o-mini (`config.yaml > LLM > 에이전트별_모델`).
- 실패 사례 정리: [실패사례_검증과적합.md](실패사례_검증과적합.md)

## 남은 일 (우선순위 순)

1. **테스트 0.7 이상 시도: 달 길이 변수 추가** (가장 유망)
   - EDA에서 "다음 달 일수 − 이번 달 일수"와 월별 증가 비율의 상관이 r = 0.71이었다 (n=9개월, 참고용). 정답이 '월 합계' 기준이라 달이 길면 늘어나기 쉽다.
   - 지금 달력변수에는 다음 달 영업일 수만 있고 **이번 달 대비 일수·영업일 수 차이**가 없다.
   - 할 일: `agents/data_agent.py`의 `_calendar()`에 `일수차이`, `영업일수차이` 추가 → `config.yaml > 변수`에 항목 추가(처음값 끄기, 시험 예) → 실행해 비교.
   - 미리 알 수 있는 달력 정보라 누수가 아니다.
2. 수정 루프 과적합 줄이기: 채택 규칙 강화(3개월 모두 상승, 부트스트랩 95%) 또는 `수정_최대횟수` 1~2로 비교 실험.
3. 데이터 담당(gpt-4o-mini)의 사전 점검 판단이 매번 "진행"이고 이유 문장이 어색함 → gpt-4.1로 올려 비교.
4. 문제 정의를 바꾸는 선택지 (팀 결정 필요, 점수 비교가 이전과 달라짐):
   - 정답을 '일평균 지출' 기준으로 (EDA: 월합계 기준과 정답 일치율 85.9%)
   - ±2% 이내 미세변동을 평가에서도 제외
5. optuna 설치 후 `탐색 > 방법: optuna` 비교 (지금은 미설치라 grid로 대체됨).

## 실행 방법 요약

```powershell
.venv\Scripts\python run.py --check --llm openai     # 설정 확인
.venv\Scripts\python run.py --llm openai             # 실데이터, 6개 에이전트 LLM 모드
.venv\Scripts\python run.py                          # 규칙 모드
.venv\Scripts\python tools\self_test.py              # 안전장치 자동 점검 (가짜데이터)
```

## 지켜야 할 것

- 원본 데이터(`데이터/데이터셋(읽으면안됨)/`)는 읽거나 출력하지 않는다. 결과·화면·LLM에는 집계값과 지역 코드만.
- 테스트는 고르는 데 쓰지 않는다 (실행당 1회, `test_log.csv`에 기록).
- 커밋 메시지에 Co-Authored-By 줄을 넣지 않는다 (사용자 요청).
- push 전에 `git pull --rebase` (GitHub에서 직접 수정하는 경우가 있음).
